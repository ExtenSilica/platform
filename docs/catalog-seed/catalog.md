# ExtenSilica — RISC-V ISA Extension Package Catalog

The agent in [`docs/catalog-seed/agent-prompt.md`](./agent-prompt.md) processes
**one row at a time**: fetches the upstream repo, extracts whatever opcodes /
encodings / metadata it can find, builds a valid `.xsil`, and publishes it to
the production registry as a **spec-derived scaffold** (`readinessLevel: 1`,
keyword `catalog-seed`).

When a row is published, mark its checkbox at the end so the next run skips it.

## Honest framing

Each row carries a **`Standard`** classification (mirrored into
`metadata.catalogSeed.standardStatus` in the manifest) and an **`Authority`**
(the entity behind the spec). This is the ground-truth signal the homepage and
the package badge use to keep the catalog honest:

| Status      | Meaning                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------- |
| `ratified`  | Frozen specification approved by RISC-V International. Listed on https://riscv.org/specifications/ratified/. |
| `draft`     | Working draft published under RISC-V International or another standards body; not yet ratified.              |
| `vendor`    | Custom extension defined and shipped by a commercial vendor (T-Head, SiFive, Qualcomm, …).                   |
| `research`  | Academic / experimental extension, typically no production users yet.                                        |
| `custom`    | Bespoke / one-off extension that does not fit the categories above.                                          |

Of the rows below, **29 are ratified** RISC-V International crypto extensions /
bundles. The remaining rows are vendor, draft, or research. Catalog headlines
should always reflect that mix — never imply that every row is a standard.
